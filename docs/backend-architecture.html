Aerotrace · Technical Overview

Backend Architecture

ESP32 / SIM7600G · LTE · Firebase · SD Card Upload

What is Aerotrace?

Aerotrace is a flight school management system. A small electronic box (the FDR — Flight Data Recorder) is installed in each aircraft. It records GPS position, speed, altitude, heading, RPM, CO levels, and more — then sends this data over the mobile network (4G LTE) to a cloud database. Instructors can watch every aircraft in real time on a map, and replay any flight in full detail after landing.

The Hardware Box

Component Role
LILYGO T-SIM7600G Main computer + 4G LTE modem. Runs the firmware, connects to the cloud, sends data every 5 seconds.
SD Card Local storage. The full flight log (1 data point per second) is written here during the flight as a CSV file.
LILYGO T-RGB 2.8" Small touchscreen in the cockpit. Shows flight status, pilot info, and warnings. Connected via Bluetooth.
GPS + Sensors Provides lat/lon, altitude, speed, heading. Additional sensors for RPM and CO (carbon monoxide).
SIM Card (Emnify) 4G LTE connectivity. Works across Europe on any carrier tower.

The Four Operating Modes

MODE_PREFLIGHT

Before Take-Off

Box powers on. GPS acquires position. Pilot identifies themselves (PIN code, NFC card in future). System sends a "ready" status to the cloud every 5 seconds. Aircraft appears as grounded on the instructor map.

MODE_FLIGHT

In Flight

Box sends position, speed, altitude, heading, RPM and CO every 5 seconds via 4G LTE. All data is also saved locally to the SD card at 1 point per second for full-resolution replay later. Aircraft appears as airborne on the map.

MODE_POSTFLIGHT

After Landing ← NEW

Aircraft is back on the ground. Box continues sending status. Then it reads the CSV flight log from the SD card and uploads it to the cloud automatically. Once done, the flight appears in the logbook for replay.

MODE_SLEEP

Parked

Upload complete. Box powers down most systems to save power. Aircraft disappears from the live map after a timeout.

SD Card Upload — After Landing (To Build)

During the flight, the SD card stores 1 data point per second — much higher resolution than the 5-second live feed. This is the full flight log used for replay, charts, and debriefing. After landing, it needs to go to the cloud.

Why not just use the live 5-second data for replay?
The 5-second data is fine for a live map dot. But for smooth replay, charts, instrument simulation, and safety analysis, you need every second. A 2-hour flight = 7,200 data points. That detail only lives on the SD card.

Upload Method: Resumable Chunked Upload

A 2-hour flight CSV file is roughly 1.5 MB. Over 4G LTE in a rural airfield, the connection can be slow or briefly drop. A "resumable" upload solves this: the file is cut into small chunks, and if the connection drops, the upload resumes from where it stopped — no need to start over.

Firebase Storage (Google's file hosting) supports this natively via its REST API. The ESP32 can call it directly using the same API key already used for the database — no extra server needed.

What the Dashboard Receives

Live Map (EnVolPage)

Shows all aircraft in real time. Each dot is updated every 5 seconds from the FDR. Colour indicates status: airborne, grounded, uploading. Instructors see all club aircraft at a glance.

Logbook (LogbookPage)

Once the SD card upload is complete, the flight appears here automatically. Instructor can assign it to a pilot, verify duration and route, then open it in Replay.

Replay (ReplayPage)

Full 1-second resolution playback. 2D/3D map, six-pack instruments (airspeed, altitude, attitude, heading, VSI, turn coordinator), colour-coded flight phase trail, charts.

Live Traffic (LivePage)

Overlays nearby ATC traffic from SafeSky on the map alongside the club's own aircraft. Gives instructors situational awareness of the surrounding airspace.

Key Design Decisions

No extra server needed. The ESP32 talks directly to Firebase (database + file storage) using Google's public REST API. One less thing to maintain and pay for.

Resumable upload handles LTE drops. Rural airfields often have weak signal. Chunked upload means a 30-second signal drop doesn't restart a 10-minute file transfer.

SD card as truth, cloud as distribution. Even if the LTE connection fails completely, the full flight data is safe on the SD card. Upload can be retried next time the box powers on.

Future: NFC pilot identification. Currently the pilot identifies by PIN code. A NFC card reader (PN532) is planned to make it one-tap identification.
